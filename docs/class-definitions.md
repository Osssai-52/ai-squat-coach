# 오류 클래스 정의 (확정본 — 45° 촬영 기준)

> 촬영·데모 각도: **45° 반측면으로 전 과정 통일** (수집 데이터가 45°라서 학습과 추론의 시점을 일치시킴).
> 영상·사진·발표 데모 모두 같은 각도여야 함 — 시점이 다르면 모델이 카메라 각도를 학습해 버림.

## 분류 클래스 5개

| 코드 | 이름 | 어떻게 보이는가 (최저점 기준) | 핵심 피처 |
|---|---|---|---|
| `good` | 정상 | 허벅지가 수평 근처까지 내려가고 허리가 곧음 | 전부 |
| `depth` | 깊이 부족 (하프스쿼트) | 엉덩이가 충분히 안 내려감 | knee_angle 큼 |
| `back` | 허리 굽음 (Forward Lean) | 허리가 지나치게 숙여지며 엉덩이만 들림 | trunk_lean 큼, hip_angle 작음 |
| `heel` | 발뒤꿈치 들림 (Heel Lift) | 발목 가동성 부족으로 까치발이 됨 | foot_angle 큼 |
| `knee` | 무릎 모임 (knee valgus) | 내려갈 때 무릎이 안쪽으로 꺾임 | knee_ankle_ratio 작음 |

- `knee`는 45° 통일 덕분에 포함 가능해짐 (완전 측면이었다면 관측 불가).
  전용 피처 = **양 무릎 간격 ÷ 양 발목 간격** — 무릎이 모이면 1보다 작아짐.
- **검증 조건부**: 실데이터 학습 후 confusion matrix에서 knee가 good과 구분 안 되면
  v1에서 제외하고 "향후 과제"로 발표 (데이터는 이미 확보).

## 판정 시점

- 프레임 단위가 아니라 **렙의 최저점 프레임에서만 판정** (최저점 = 무릎 각도 최소 프레임)
- 학습 데이터도 동일 기준: 영상에서 최저점 ±15° 프레임만 추출 (extract_features.py가 자동 처리)

## 규칙 기반 v0 임계값 (측면 기준 추정값 — 45° 실측으로 반드시 재튜닝)

판정 우선순위 순서대로:
1. 깊이 부족: 무릎 각도 > 100°
2. 허리 굽음: 허리 기울기 > 50°
3. 발뒤꿈치 들림: 발 각도(뒤꿈치→발끝 vs 수평) > 25°
4. 무릎 모임: 무릎/발목 간격비 < 0.7
5. 그 외: 정상

- 서 있음 판정: 무릎 각도 ≥ 160°
- **재튜닝 방법**: 운동 화면 "디버그 ⚙" 패널을 켜고 45° 각도에서 정상/각 오류 자세를
  취하며 값이 실제로 갈리는 지점을 확인 → frontend CONFIG와 ml/train.py에 동일하게 반영
